# 미스터 월드 테마 여행 서비스

소프트웨어공학(71032) 프로젝트 — 팀 아메리카노. 테마(허니문·효도·골프·트레킹)와 투어 등급을 고르고, 호텔·식사·교통을 바꿔 예약하는 고객 화면과, 출발 일정·상품 기획·기념품 재고를 관리하는 직원 화면, 그리고 이를 지원하는 서버(API + SQLite DB)로 구성됩니다.

## 실행 방법

Node.js **22.13 이상** (권장 24 이상)이 필요합니다. DB는 Node 내장 `node:sqlite`를 쓰므로 따로 설치할 DB 서버가 없습니다.

```bash
npm install
npm start
```

| 화면 | 주소 | 데모 계정 |
| --- | --- | --- |
| 고객 화면 | http://localhost:3000/ | `demo` / `1234` (완료 여행 3회, 단골 고객) |
| 직원 화면 | http://localhost:3000/staff | `staff` / `1234` |

- 처음 실행하면 `data/worldtour.db`가 만들어지고 데모 데이터(고객 5명, 직원 1명, 지난 여행·예정 예약)가 들어갑니다.
- 데이터 초기화: `npm run reset-db` 또는 직원 화면 하단의 "데모 데이터 초기화".
- 테스트: `npm test` (API 통합 테스트 15개, 날짜를 2026-11-16으로 고정해 메모리 DB에서 실행)
- 다른 고객 계정: `sky`, `sea`, `forest`, `joy` (비밀번호 모두 `1234`)

> `index.html`을 파일로 직접 열면 서버에 연결할 수 없다는 안내가 나옵니다. 반드시 `npm start` 후 주소로 접속하세요.

## 배포 (Render)

1. 이 코드를 GitHub 저장소에 올립니다 (Render는 GitHub 저장소를 연결해 배포).
2. https://dashboard.render.com → **New → Blueprint** → 저장소 선택 → **Apply**. 저장소의 `render.yaml`대로 Node 24 웹 서비스가 만들어집니다.
   (Blueprint 대신 **New → Web Service**로 만들 경우: Build `npm ci`, Start `npm start`, 환경변수 `NODE_VERSION=24`, `TZ=Asia/Seoul`)
3. 몇 분 뒤 `https://<서비스이름>.onrender.com` 주소가 생깁니다. 직원 화면은 그 주소 뒤에 `/staff`.
4. **자동 배포:** `main`에 push하면 GitHub Actions가 `npm test`를 돌리고, 통과하면 Render Deploy Hook으로 재배포합니다 ([.github/workflows/render-deploy.yml](.github/workflows/render-deploy.yml)). 처음 한 번 Render의 Branch를 `main`으로 바꾸고, Deploy Hook 주소를 GitHub secret `RENDER_DEPLOY_HOOK_URL`에 등록해야 합니다 (방법은 파일 맨 위 주석).
5. 이전 버전으로 되돌리는 방법과 백업 브랜치는 [docs/rollback.md](docs/rollback.md)를 참고하세요.

무료 플랜 주의사항:
- 15분 동안 접속이 없으면 서버가 잠들고, 다음 접속 때 깨어나는 데 1분 정도 걸립니다. 발표 직전에 한 번 접속해 두세요.
- 무료 플랜은 디스크가 유지되지 않아 **재배포·재시작하면 DB가 데모 초기 상태로 돌아갑니다.** 시연용으로는 문제없지만, 데이터를 계속 보관하려면 유료 디스크나 외부 DB(PostgreSQL)가 필요합니다.

## 주요 업무 규칙

- **출발 확정:** 허니문 낭만 투어는 같은 출발일에 **2팀 이상**, 그 외 테마는 **신청 인원 3명 이상**이면 자동 확정 → 예약자 전원에게 문자(시뮬레이션) 발송 + 기념품 자동 출고. 기준은 직원 화면에서 테마별로 바꿀 수 있습니다.
- **등급 제한:** 허니문·효도 투어는 그랜드 스타일 이상. 호텔·식사도 그 등급 기본값 미만으로 내릴 수 없습니다.
- **단골 할인:** 완료된 여행 1–2회 5%, 3회 이상 10%.
- **모의 결제:** 상품을 고르고 "결제하기" → 결제 화면(신용·체크카드 / 실시간 계좌이체 / 간편결제)에서 결제하면 예약이 완료됩니다. 실제 결제는 이루어지지 않으며, 카드 번호는 브라우저에서 형식(Luhn)만 검사하고 서버에는 끝 4자리만 보냅니다. 테스트 카드: `4242 4242 4242 4242`. 예약을 취소하면 '환불 완료'로 바뀝니다.
- **가격:** 화면에서 미리 계산하지만, 예약 시 서버가 다시 계산해 저장합니다. 그 사이 직원이 가격표를 바꿨으면 신청을 막고 새 금액을 안내합니다.

자세한 내용은 [docs/backend.md](docs/backend.md)를 참고하세요.

## 음성으로 상품 찾기

고객 화면 홈의 **음성으로 말하기** 버튼을 누르고 원하는 여행을 말하면, 해당 테마의 상품 선택 화면이 열리고 말한 조건이 미리 채워집니다.

- 인식: 브라우저 내장 Web Speech API (`ko-KR`). Chrome·Edge에서 동작하며 인터넷 연결이 필요합니다. 별도 API 키나 서버 설정은 없습니다.
- 마이크는 `https://` 또는 `http://localhost`에서만 쓸 수 있습니다 (Render 주소, `npm start` 모두 해당).
- 테마: 고정 키워드(허니문·신혼·커플 / 효도·부모님·힐링 / 골프·라운딩 / 트레킹·등산·아웃도어 등) + 테마 이름 + 여행지 이름으로 찾습니다. 직원이 새로 만든 테마도 이름으로 찾을 수 있습니다.
- 함께 인식하는 조건: 여행지("경주", "몰디브"), 기간("3박", "사박"), 인원("4명", "다섯 명").
  여행지만 말하면 그 여행지가 한 테마에만 있을 때 그 테마로 연결하고, 여러 테마에 있으면("제주") 테마를 다시 묻습니다.
- 음성인식이 안 되는 브라우저이거나 마이크가 없으면 같은 영역의 **글로 입력하기**를 쓰면 됩니다 (평가용 모의 입력으로도 사용 가능).
- 키워드 추가·수정: `index.html`의 `VOICE_KEYWORDS`.

### 예약 화면에서 옵션 바꾸기

상품 선택(예약) 화면 위쪽의 **음성으로 옵션 바꾸기**에서 말하면 옵션이 바로 바뀌고 결제 예정 금액을 알려 줍니다. 한 문장에 여러 옵션을 말해도 됩니다 (예: "치앙마이로 4박 5일, 5성급 호텔에 커피 추가").

| 옵션 | 말하기 예 |
|---|---|
| 여행지 | "다낭으로 바꿔줘" (다른 테마의 여행지·테마를 말하면 그 상품으로 이동: "몰디브 가고 싶어") |
| 기간 | "4박 5일", "사박", "하루 더" |
| 출발일 | "12월 5일 출발", "두 번째 출발일", "다음 출발일", "가장 빠른 날짜", "확정된 일정" |
| 인원 | "네 명", "한 명 추가", "두 명 빼줘" |
| 투어 등급 | "프리미엄으로" (호텔·식사는 그 등급 기본값으로) |
| 호텔 · 식사 · 교통 | "5성급 호텔", "도시락 말고 현지식", "10인 승합으로", "차량 없이" |
| 추가 메뉴 | "커피 추가", "샴페인 빼줘" |
| 기타 | "기본 구성으로", "얼마야?", "결제할게", "뭐라고 말하면 돼?" |

- 상품 규칙(최소 등급, 허니문 2인 전용, 최대 인원, 차량 정원)에 맞지 않는 요청은 바꾸지 않고 이유를 알려 줍니다.
- 말 목록 수정: `index.html`의 `VOICE_STYLE`, `VOICE_HOTEL`, `VOICE_MEAL`, `VOICE_VEHICLE`, `VOICE_ADDON`.
